# AI Tutor 脚本质量评估清单

用这个清单来评估生成的讲解脚本是否达到"经验丰富教师"的水平。

## 第一部分：整体结构与流程

### 1.1 课程架构

- [ ] **有明确的开场（Intro）**：5-10秒，建立课程主题和学生预期
  ```
  好示例："今天我们看一个关于全球变暖的新闻。
          你会学到新闻语言的特点，特别是记者怎样
          保持中立和准确性。准备好了吗？"
  ```

- [ ] **有明确的结尾（Outro）**：总结重点、鼓励学生
  ```
  好示例："我们今天学了'allegedly', passive voice, 还有记者的思维方式。
          这些是新闻英文的基础。你现在可以听新闻时
          注意这些特点。很棒！"
  ```

- [ ] **有逻辑进度**：从简单到复杂，从已知到未知

### 1.2 讲解的均衡

- [ ] **Light讲解占比合理**（快速过渡句子，30-40%）
  
- [ ] **Standard讲解占比合理**（一般讲解，40-50%）
  
- [ ] **Deep讲解占比合理**（只在关键点，10-20%）

- [ ] **能量曲线变化**：不是一直都很深，有高有低

### 1.3 课程长度

- [ ] **时间分配合理**：没有一个句子讲得过长（除非特别重要）
  - Light: 20-40秒
  - Standard: 1.5-3分钟
  - Deep: 4-8分钟

## 第二部分：讲解质量

### 2.1 意义清晰（Meaning）

- [ ] **学生知道单词的定义吗？**
  ```
  ✓ "'Allegedly' means据说或想必是某事，但未经证实"
  ✗ "'Allegedly' is a hedge"
  ```

- [ ] **学生理解为什么这个定义重要吗？**
  ```
  ✓ "为什么?因为记者需要保护自己不被告"
  ✗ 只给了定义，没有解释为什么
  ```

- [ ] **定义是否用学生能理解的语言？**
  - 避免复杂的语言学术语
  - 用日常语言解释

### 2.2 用法清晰（Use）

- [ ] **学生知道这个词/语法**在哪些情境下使用吗？**
  ```
  ✓ "'Allegedly' 在新闻报道中使用，而不是日常谈话"
  ✗ 没有提及使用情境
  ```

- [ ] **学生知道"不能用它在哪里"吗？**
  ```
  ✓ "你不会说'I allegedly ate breakfast'（你知道你吃了）"
  ✗ 只讲了"怎样用"，没讲"不怎样用"
  ```

- [ ] **提供了真实的例子吗？（来自真实文本）**
  ```
  ✓ 从新闻报道、视频对话中直接提取
  ✗ 人工编造的、没人这样说的例子
  ```

### 2.3 对比（Contrast）

- [ ] **与相似词汇有对比吗？**
  ```
  ✓ "Allegedly vs Supposedly vs Reportedly — 有什么区别？"
  ✗ 只讲了'Allegedly'，没有对比
  ```

- [ ] **与母语有对比吗？（对非英语学习者）**
  ```
  ✓ "中文的'据说'有法律含义吗？"
  ✗ 没有提及母语对比
  ```

- [ ] **形式和意义都有对比吗？**
  ```
  ✓ "Being + -ed（被动）vs 主动语态"
  ✗ 只对比意义，不对比形式
  ```

### 2.4 文化与背景（Cultural Context）

- [ ] **讲解是否包含为什么英文这样说的背景？**
  ```
  ✓ "这反映了英文文化对明确沟通和法律责任的重视"
  ✗ 只讲了语言，没讲文化
  ```

- [ ] **是否提到这个表达背后的故事？**
  ```
  ✓ "Serendipity来自一个波斯童话故事..."
  ✗ 直接给定义，没有故事
  ```

- [ ] **是否邀请学生对比自己的文化？**
  ```
  ✓ "你们的文化中...怎么说？"
  ✗ 一方向讲解
  ```

## 第三部分：互动与参与度

### 3.1 提问（Questions）

- [ ] **讲解中有足够的提问吗？**（至少每3-4分钟有一个）
  ```
  ✓ 讲解中穿插提问，不是讲完再问
  ✗ 讲解完全单向，最后一次性问
  ```

- [ ] **提问的质量好吗？**（检查每个提问）
  - [ ] 清晰明确
  - [ ] 有趣、引发思考
  - [ ] 开放式（允许多个答案）或闭合式（有唯一答案）的搭配合理
  - [ ] 符合学生水平

- [ ] **是否给了充足的等待时间？**（3-5秒）
  ```
  ✓ "[沉默3秒]"
  ✗ 问完立即回答
  ```

- [ ] **是否有后续提问来深化？**
  ```
  ✓ Q1: "What does it mean?" 
       Q2: "Why would a journalist use it?"
       Q3: "Can you create an example?"
  ✗ 只问一次，然后继续
  ```

### 3.2 反馈（Feedback）

- [ ] **如果提出了问题，是否有反馈？**
  ```
  ✓ "好想法，还有其他想法吗？"
  ✗ 问了问题但没有对答案的反应
  ```

- [ ] **反馈是积极的并推进讨论吗？**
  ```
  ✓ "Exactly! And this shows that..."
  ✗ "That's wrong."
  ```

### 3.3 应用机会（Application）

- [ ] **学生有机会用新词汇/语法造句吗？**
  ```
  ✓ "现在你试试用'allegedly'讲个故事"
  ✗ 只讲，不让学生应用
  ```

- [ ] **应用任务是否真实且有意义？**
  ```
  ✓ "创作一个新闻标题，用到学到的词汇"
  ✗ "造一个'allegedly'的句子"（太刻板）
  ```

## 第四部分：讲解的自然度与沉浸感

### 4.1 语言风格（Tone & Style）

- [ ] **讲解听起来自然、像真人吗？**
  ```
  ✓ "所以'allegedly'...让我告诉你为什么这个词很强大。"
  ✗ "'allegedly'定义为...第一...第二...第三..."
  ```

- [ ] **是否有真诚的热情而不是机械执行？**
  ```
  ✓ "这是一个很有趣的词！"
  ✗ "这是一个词汇点。"
  ```

- [ ] **是否有自然的停顿和思考？**
  ```
  ✓ "嗯...让我想想怎样解释这个最好..."
  ✗ 每句话都完美流畅，像读稿子
  ```

- [ ] **是否避免了模板化表达？**
  ```
  ✗ 避免："首先...其次...第三...最后..."
  ✗ 避免："一起来看..."（重复过多）
  ✓ 用自然的过渡句
  ```

### 4.2 个性化与灵活性（Personalization）

- [ ] **讲解是否连接到学生的现实生活？**
  ```
  ✓ "你有过serendipity的经历吗？比如...?"
  ✗ 纯粹的语言讲解，没有个人联系
  ```

- [ ] **是否承认学生可能有不同的背景？**
  ```
  ✓ "如果你是法律专业...如果你没有法律背景..."
  ✗ 假设所有学生都有相同的知识
  ```

- [ ] **是否有开放式评论邀请学生参与？**
  ```
  ✓ "你怎么想？"
  ✗ "这就是...继续下一个。"
  ```

### 4.3 教师的"透明思维"（Visible Thinking）

- [ ] **是否有地方显示教师在思考或发现？**
  ```
  ✓ "有趣的是...我没想到这个词有这样的历史"
  ✗ 显得教师什么都已经知道了
  ```

- [ ] **是否允许"修正"或"补充思考"？**
  ```
  ✓ "实际上，让我重新表述一下这个..."
  ✗ 第一次讲解必须完美
  ```

## 第五部分：内容准确性与完整性

### 5.1 准确性

- [ ] **语言形式是否准确？**
  - 词汇定义正确吗？
  - 语法解释正确吗？
  - 发音指导正确吗？

- [ ] **例子是否真实有效？**
  - 来自真实文本吗？
  - 是否有语境支持？

- [ ] **文化/背景信息是否正确？**
  - 历史事实正确吗？
  - 文化观察公平吗？

### 5.2 完整性

- [ ] **是否覆盖了所有关键点？**
  ```
  检查课程计划(lesson plan)：
  ✓ 所有标记为"deep"的句子都讲了
  ✓ 所有标记为"replay"的句子都重放了
  ✓ 所有标记为"question"的句子都有提问
  ```

- [ ] **是否有任何遗漏的关键词汇？**

- [ ] **是否回应了课程计划中的所有教学目标？**

## 第六部分：技术与格式

### 6.1 脚本格式

- [ ] **脚本格式是否清晰？**
  ```
  ✓ type: "speak" / "play_sentence" / "explain_sentence" 等
  ✓ 每个操作有清晰的目的
  ```

- [ ] **每个"speak"（讲话）的文本是否TTS友好？**
  - 没有太多标点符号
  - 句子长度适中（不超过20秒）
  - 自然的语音节奏

### 6.2 音频相关

- [ ] **是否包含了"play_sentence"指令？**
  ```
  ✓ 每个讲解后都有一次重放
  ✓ Deep句子有多次重放
  ```

- [ ] **TTS文本是否经过优化？**
  - 含有自然的停顿标记
  - 强调词汇清晰
  - 节奏自然

## 第七部分：对标准的检查

### 7.1 与"经验丰富教师"的对标

- [ ] 讲解感觉像是来自 **有10年经验** 的教师吗？
- [ ] 学生会感受到 **真诚的关心和专业**吗？
- [ ] 讲解是否体现了 **教学艺术和科学**的结合?
- [ ] 学生事后是否会说"我现在真的理解了"?

### 7.2 与同类课程的对标

- [ ] 与其他优质教程相比，讲解深度如何？
- [ ] 互动频率是否充足？
- [ ] 个性化程度如何？

## 评分系统

### 评估分数（0-100）

计算方法：
```
第一部分（整体结构）：满分20分
第二部分（讲解质量）：满分20分
第三部分（互动参与）：满分20分
第四部分（自然度）：满分20分
第五部分（准确完整）：满分20分

总分 = (所有检查项通过数 / 总检查项数) × 100
```

### 及格线

- **80-100分**：优秀，达到"经验丰富教师"水准
- **60-79分**：良好，需要小改进
- **40-59分**：一般，需要主要改进
- **<40分**：不合格，需要重新生成

### 改进建议

如果分数低于80分，优先改进这些方面（按优先级）：
1. **第三部分（互动）** — 最直接影响学生沉浸感
2. **第四部分（自然度）** — 最直接影响听众反应
3. **第二部分（讲解质量）** — 最直接影响学习成果
4. **第一部分（结构）** — 最直接影响整体流程
5. **第五部分（准确性）** — 最直接影响可信度

## 快速检查（30秒版本）

如果你只有30秒，检查这5点：

- [ ] **有互动吗？**（提问、应用）
- [ ] **讲解听起来自然吗？**（不像模板）
- [ ] **有多个例子和对比吗？**
- [ ] **是否覆盖了所有关键点？**（对比lesson_plan）
- [ ] **学生能应用吗？**（有应用任务吗）

如果全是"是"，这个脚本大概可以用。
如果有"否"，需要返工。
